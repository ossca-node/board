## 문제

PR #65351과 유사한 리팩토링 작업입니다. 동일한 패턴의 코드가 나타나는 12개의 테스트 파일에 대해 수정 작업을 완료했습니다.

## 해결

빠른 approve를 받기 위해 PR #65351에서 먼저 하나의 파일에 대해서 리팩토링을 완료한 후, 같은 패턴이 반복되는 파일 여러 개를 수정하는 PR을 나중에 올린 뒤 PR #65351을 PR 메시지에 언급했습니다. 리뷰어들이 같은 작업임을 빠르게 이해할 수 있도록 했습니다.

`spawnSync()`에 대한 헬퍼 함수는 3개가 있습니다.

이 중 2개는 status:0, signal:null인지를 기본으로 검사합니다.

- `spawnSyncAndAssert()`: 추가적으로 stdout, stderr 출력값에 대한 체크도 해야 할 때 사용합니다. 인자 개수는 4개입니다.
- `spawnSyncAndExitWithoutError()`: 출력값 체크가 없습니다. 인자 개수는 3개입니다.

나머지 1개는 검사할 status와 signal 값도 임의로 지정할 수 있습니다.

- `spawnSyncAndExit()`

PR #65351과 달리 `status`가 0인지만 체크하고, `signal` 값에 대한 assert이 없는 코드에 대해서도 헬퍼 함수를 추가해봤습니다.

`status`가 0이 아닐 때를 대비해 하드코딩됐던 console.log문은 모두 제거했다. `expectSyncExit()`의 내부 함수 `logAndThrow()` 가 이를 대체하기 때문입니다.

다만 `status`, `signal`의 값과 상관없이 의도적으로 로그를 찍는 코드의 경우는 살려뒀습니다(test-v8-*.js 에 있는 console.log 들).
