## 문제

`src/ffi/data.cc` 정수 setter는  `IsNumber()`로 입력 타입을 검증하지만, float setter는 `ToNumber()`로 값을 강제 변환하고 있었습니다.

그 결과 `setFloat64(ptr, 0, value)`에 숫자가 아닌 값을 전달 하면 타입 코어싱(Type Coercion)이 발생해서 

- `'1.5'` → `1.5`
- `true` → `1`
- `{}` → `NaN`
- `null` → `0`

문서에도 setter가 메모리에 쓰기 전에 값을 대상 네이티브 타입에 맞게 검증한다고 명시되어 있었지만, 검증을 하지 않은채로 Type Coercion이 발생한 값을 네이티브 메모리에 넣게 되어, 크래시가 발생할수 있는 상황이었습니다.


또한 `valueOf()`가 예외를 던지는 객체를 전달하면 `ToNumber()`가 남긴 pending exception을 `THROW_ERR_INVALID_ARG_VALUE`가 덮어썼습니다. 

해당 문제는 [issue #65341](https://github.com/nodejs/node/issues/65341)를 먼저 올린 다음 PR을 진행했습니다.

## 해결

우선 부동소수점 setter의 `ToNumber()` 변환을 `IsNumber()`을 통해 검사 하도록 수정하였습니다.

에러 메시지는 기존 코드의 표현에 맞춰 타입별로 구분했습니다.
- `Value must be a float`
- `Value must be a double`

더 이상 필요하지 않은 `v8::Context`, `v8::MaybeLocal` 선언과 지역 변수도 함께 제거했습니다.

## 검증

`test/ffi/test-ffi-memory.js`에 아래 테스트를 추가했습니다.

- `setFloat32`: `'1.5'`, `null` 거부
- `setFloat64`: `'1.5'`, `true`, `{}` 거부
- 타입별 에러 메시지 확인
- `{ valueOf: common.mustNotCall() }`을 사용해 강제 변환이 발생하지 않음을 확인
