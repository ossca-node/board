## 문제 내용

`internalBinding('heap_utils')`를 통해 Node.js 내부 C++ 바인딩을 JS 객체로 가져오는 과정에서 `heap_utils`에 사용 가능한 함수와 각 함수의 시그니처를 타입으로 정의하여 자동완성을 지원하고자 했습니다.

## 해결 과정과 검증

#### 1. 함수와 시그니처 파악

`heap_utils`에 어떤 함수를 제공하고 각 함수가 어떻게 사용되는지를 파악하며 함수의 시그니처를 파악해야 했습니다.

`internalBinding()`은 C++ 바인딩을 JS객체로 가져올 수 있도록 하는 함수이기 때문에, `heap_utils`가 정의된 네이티브 코드와 이를 활용하는 JS 코드를 비교하며 타입을 정의해야 했습니다.

우선적으로 JS 코드에서 `internalBinding('heap_utils')`을 통해 호출하는 함수는 총 3가지 였습니다.

```js
const {
  createHeapSnapshotStream,
  triggerHeapSnapshot,
} = internalBinding('heap_utils');

const { buildEmbedderGraph } = internalBinding('heap_utils');
```

그리고 해당 함수가 정의된 네이티브 코드는 `heap_utils.cc`에서 확인할 수 있었습니다.

```c++
void CreateHeapSnapshotStream(const FunctionCallbackInfo<Value>& args) {}

void TriggerHeapSnapshot(const FunctionCallbackInfo<Value>& args) {}

void BuildEmbedderGraph(const FunctionCallbackInfo<Value>& args) {}

SetMethod(context, target, "buildEmbedderGraph", BuildEmbedderGraph);
SetMethod(context, target, "triggerHeapSnapshot", TriggerHeapSnapshot);
SetMethod(context, target, "createHeapSnapshotStream", CreateHeapSnapshotStream);
```

`heap_utils.cc` 파일 내에서 `SetMethod`를 통해 JS로 바인딩을 맺는 함수는 총 3개이기 때문에 그 함수들에 대해서 타입을 정의하도록 하였습니다.

- [TriggerHeapSnapshot](https://github.com/nodejs/node/blob/37aeecc7b6c991048f0d9157840d081d7c67e5c9/src/heap_utils.cc#L456)
```c++
void TriggerHeapSnapshot(const FunctionCallbackInfo<Value>& args) {
  ...
  CHECK_EQ(args.Length(), 2);
  Local<Value> filename_v = args[0];
  auto options = GetHeapSnapshotOptions(args[1]);

  if (filename_v->IsUndefined()) {
    ...
    if (String::NewFromUtf8(isolate, *name).ToLocal(&filename_v)) {
      args.GetReturnValue().Set(filename_v);
    }
    return;
  }
```

해당 메서드에서 `args`는 총 2개를 받고 하나는 `filename_v`와 나머지 하나는 `GetHeapSnapshotOptions()`에 전달됩니다. 해당 메서드를 한 번 더 타고 들어가면 다음과 같이 타입을 검사합니다.

```c++
HeapProfiler::HeapSnapshotOptions GetHeapSnapshotOptions(
    Local<Value> options_value) {
      CHECK(options_value->IsUint8Array());
      ...
    }
```

이에 대해 두 번째 매개변수는 `Uint8Array`의 타입을 갖고 있다는 것을 알 수 있습니다.

filename_v가 undefined이면 기본 파일명을 생성해 문자열로 반환합니다. 파일명이 전달되면 해당 경로에 snapshot을 저장한 뒤 전달받은 값을 반환합니다.

이를 보았을 때, `TriggerHeapSnapshot()`는 다음과 같이 표현될 수 있습니다.

```js
triggerHeapSnapshot(filename: string | undefined, options: Uint8Array): string;
```

- [BuildEmbedderGraph](https://github.com/nodejs/node/blob/37aeecc7b6c991048f0d9157840d081d7c67e5c9/src/heap_utils.cc#L211)
```c++
void BuildEmbedderGraph(const FunctionCallbackInfo<Value>& args) {
  ...
  // This binding is used only by tests. Include supplied values so tests can
  // verify that JSGraph returns one graph node for each distinct V8 value.
  for (int i = 0; i < args.Length(); i++) {
    graph.V8Node(args[i]);
  }
  Local<Array> ret;
  if (graph.CreateObject().ToLocal(&ret))
    args.GetReturnValue().Set(ret);
}
```

위 함수에서는 매개변수가 배열의 형태를 갖고 있는 것을 알 수 있습니다. 하지만 주석에서는 이 함수가 테스트를 위한 함수라는 것을 명시하고 있기에 실제 JS에서 이 함수를 어떻게 사용하는 지를 확인하였습니다.

```js
let _buildEmbedderGraph;
function buildEmbedderGraph() {
  if (_buildEmbedderGraph) { return _buildEmbedderGraph(); }
  ...
  ({ buildEmbedderGraph: _buildEmbedderGraph } = internalBinding('heap_utils'));
  return _buildEmbedderGraph();
}
```

실제 해당 `_buildEmbedderGraph`를 호출하고 저장할 때는 별도의 매개변수를 전달하고 사용하지 않는 것을 확인하였습니다. 이에 대해서 테스트를 위한 함수이며 실제 호출할 때는 매개변수를 사용하지 않는다는 것을 판단하여 별도의 매개변수없이 객체를 반환하도록 타입을 정의하였습니다.

```js
  buildEmbedderGraph(): object[];
```

- [CreateHeapSnapshotStream](https://github.com/nodejs/node/blob/37aeecc7b6c991048f0d9157840d081d7c67e5c9/src/heap_utils.cc#L443)
```c++
void CreateHeapSnapshotStream(const FunctionCallbackInfo<Value>& args) {
  CHECK_EQ(args.Length(), 1);
  auto options = GetHeapSnapshotOptions(args[0]);
  HeapSnapshotPointer snapshot{
      env->isolate()->GetHeapProfiler()->TakeHeapSnapshot(options)};
  CHECK(snapshot);
  BaseObjectPtr<AsyncWrap> stream =
      CreateHeapSnapshotStream(env, std::move(snapshot));
  if (stream)
    args.GetReturnValue().Set(stream->object());
}
```

해당 함수의 매개변수는 1개이며 `GetHeapSnapshotOptions`로 전달하는 것을 알 수 있습니다. 
위에서 `GetHeapSnapshotOptions()`메서드가 받는 매개변수의 타입은 `Uint8Array`의 타입인 것을 확인할 수 있었습니다.

`stream`은 `HeapSnapshotStream` 인스턴스를 가리키는 포인터를 반환받게되며, `stream->object()`는 stream이 가리키는 v8 객체를 반환하게 된다. 이를 통해서만 타입을 정의할 수 없기에 실제 JS 에서 사용된 사례를 보고 타입을 정의해야 했습니다.

```js
function getHeapSnapshot(options) {
  ...
  const handle = createHeapSnapshotStream(optionArray);
  ...
  return new HeapSnapshotStream(handle);
}
```

생성된 `handle`은 `HeapSnapShotStream`의 생성자로 전달되며 인스턴스를 생성하게 됩니다. 그렇다면 해당 클래스에서 `handle`이 어떻게 사용되는 지를 파악하여 타입을 규정할 수 있습니다.

```js
class HeapSnapshotStream extends Readable {
  constructor(handle) {
    super({ autoDestroy: true });
    this[kHandle] = handle;
    handle[owner_symbol] = this;
    handle.onread = onStreamRead;
  }

  _read() {
    if (this[kHandle])
      this[kHandle].readStart();
  }
  ...
}
```

생성자는 전달받은 `handle`을 `this[kHandle]`에 저장합니다. 이후 Symbol 키인 `owner_symbol`에 현재 `HeapSnapshotStream` 인스턴스를 저장하고, `onread` 속성에는 `onStreamRead` 콜백을 할당합니다. `readStart()`는 이 과정에서 추가되는 메서드가 아니라 C++의 `StreamBase::AddMethods()`를 통해 handle의 프로토타입에 미리 등록된 네이티브 메서드입니다.

- `owner_symbol`은 `this`를 저장하며 Readable 객체가 됩니다.
- `onread`에는 네이티브 스트림이 데이터를 전달할 때 호출되는 `onStreamRead` 콜백이 저장됩니다.
- `readStart()`는 네이티브에서 정의된 메서드가 `handle`의 프로토타입에 동록된 메서드입니다.

이에 대해 다음과 같이 정의가 가능합니다.

```js
interface HeapSnapshotStreamHandle {
  [owner_symbol]?: object;
  onread?: (arrayBuffer: ArrayBuffer | undefined) => void;
  readStart(): number;
}

createHeapSnapshotStream(
  options: Uint8Array,
): InternalHeapUtilsBinding.HeapSnapshotStreamHandle;
```

#### 2. `.d.ts` 타입 정의 파일 생성

```ts
import { owner_symbol } from './symbols';

declare namespace InternalHeapUtilsBinding {
  interface HeapSnapshotStreamHandle {
    [owner_symbol]?: object;
    onread?: (arrayBuffer: ArrayBuffer | undefined) => void;
    readStart(): number;
  }
}

export interface HeapUtilsBinding {
  buildEmbedderGraph(): object[];
  triggerHeapSnapshot(filename: string | undefined, options: Uint8Array): string;
  createHeapSnapshotStream(
    options: Uint8Array,
  ): InternalHeapUtilsBinding.HeapSnapshotStreamHandle;
}
```

`owner_symbol`에 대한 정의는 `/symbols`에 정의가 되어 그대로 사용할 수 있었습니다.

#### 3. `globals.d.ts`에 바인딩

이 후 전역에서 선언한 타입 정의 파일을 사용하기 위해 바인딩을 해주었습니다.

```js
import { HeapUtilsBinding } from './internalBinding/heap_utils';

interface InternalBindingMap {
  heap_utils: HeapUtilsBinding;
}
```

## 기여 회고

- c++ 문법을 전혀 모르는 상태에서 정의된 함수를 따라가면서 타입과 함수가 어떻게 사용되는 지에 대해 감을 잡아갈 수 있었습니다.
- Node.js에서 가장 어려운 것은 어떻게, 어떤 함수가 언제 JS와 네이티브 코드에서 정의된 함수를 호출하는 지 파악하는 것이었습니다. 타이핑을 통해 그 흐름을 따라가려 노력하였지만 아직까지는 조금 감이 많이 안잡힌다고 생각이 들었습니다.
- 타입 선언 작업을 통해 JS와 네이티브 코드 사이의 호출 흐름을 따라가 보았지만, 아직 전체 구조를 파악하는 데는 더 많은 학습이 필요하다고 느꼈습니다.
